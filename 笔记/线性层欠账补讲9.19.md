# 欠账一：bias 的"自由度"到底是什么

## 1.1 先把问题缩小到一维（最简单的情形）

一个神经元：`放行条件 = w·x + b > 0`

**把 w 的长度扔掉不管**（上次讲过：w 的长度只决定"输出放大几倍"，不决定"学到什么"），只留方向和门槛。

### 没有 bias（b = 0）

```
w·x > 0        →  分界线 = w·x = 0

一维（x 是一个数）：w·x = 0  →  x = 0
                                  ↑
                          门槛被钉死在 0，焊死了
```

```
        拦下        │        放行
   ────────────────┼────────────────►  x
                   0
                   ↑
             门槛永远在这里，动不了
```

**无论 w 取什么值（1、5、100），门槛永远是 x = 0。** 因为 `w·x = 0` 里，能变的只有 w，而 x=0 时不管 w 是几，乘出来都是 0。

> ★ **w 只能改变"上升有多陡"，改变不了"从哪里开始放行"。这两个是独立的旋钮，而 b 是第二个旋钮的唯一实现方式。**

### 有 bias

```
w·x + b > 0    →   w·x > -b   →   x > -b/w

门槛 = -b/w  ← 可以放在任何地方
```

```
        拦下        │        放行
   ────────────────┼────────────────►  x
                  0.7
                  ↑
            换个 b 就能挪到这儿
```

## 1.2 ★ 为什么这个"钉死"在实际训练里是致命的

**关键在数据的取值范围。**

| 场景 | 数据范围 |
|---|---|
| 图像像素（归一化后） | `[0, 1]` —— **全在正半轴** |
| 上一层 ReLU 的输出 | `[0, +∞)` —— **全在正半轴** |
| BatchNorm 之后 | 大约 `[-3, 3]` |

假设输入是 ReLU 的输出，**全部 ≥ 0**。门槛钉在 0 会怎样？

```
数据全在这一段          │
●  ● ●●●●●●●●●●●●●●●  │
────────────────────────┼────────────────►  x
                        0
                        ↑
                  门槛在这里
```

`w·x > 0` 的放行区域是 `x > 0`。**而数据本来就全 ≥ 0 —— 于是这个神经元对几乎一切输入都放行。**

> ★★ **它退化成了一个"永远开着"的开关，什么也筛不掉。**
> **你想表达"至少要 0.7 那么强才算数"，无从表达 —— 因为门槛被焊死在 0。**

**这就是"少了一个自由度"的真实代价：不是抽象地少一种线，而是"网络失去了设置绝对门槛的能力"。**

## 1.3 二维：数一数，少的是"整整一族"

二维输入 `x = (x₁, x₂)`，分界线是一条直线。

**问：确定平面上的一条直线，需要几个数？**

```
              需要 2 个数：
                 ① 方向角 θ     ← 往哪指
                 ② 离原点距离 d  ← 离多远

                 ╲
                  ╲   d
                   ╲ ┆
        ────────────●──────────  原点
                         ╲
                          ╲
```

| | 能调几个数 | 能画出的分界线 |
|---|---|---|
| **无 bias**（`w₁x₁ + w₂x₂ = 0`）| 只有 θ（**d 被焊死为 0**）| **只有过原点的直线** |
| **有 bias**（`w₁x₁ + w₂x₂ = -b`）| θ 和 d 都能调 | **平面上所有直线** |

```
   无 bias 能画的全部                有 bias 能画的全部
   （时针：只能转，不能挪）           （还能整体平移出去）

        ╲   │   ╱                          ╲   │   ╱
         ╲  │  ╱                            ╲  │  ╱
      ────●─────                     ────●─────
         ╱  │  ╲                            ╱  │  ╲
        ╱   │   ╲                          ╱   │   ╲
                                       ┌────────────────┐
      = 一个 1 参数的族                 │  ╲  │  ╱       │
                                       │   ╲ │ ╱        │
                                       │ ───●────      │  ← 不过原点的
                                       │   ╱ │ ╲        │    那一大堆全在这
                                       │  ╱  │  ╲       │
                                       └────────────────┘
                                       = 一个 2 参数的族
```

> **少的那一族 = 所有"不过原点"的直线。** 而过原点的只是平面上直线里一个极特殊的子集 —— 随便画一条直线，它过原点的概率是 0。

## 1.4 举个会失败的具体例子

**目标**：要求 `x₁ + x₂ > 5` 才放行。

- 这条分界线是 `x₁ + x₂ = 5`。
- 把原点 `(0,0)` 代进去：`0 + 0 = 0 ≠ 5` → **不过原点**。
- → **它不在"无 bias 能画的清单"里。**

**能不能用一个无 bias 的 w 近似地实现它？** 试 `w = (1,1)`，此时放行条件是 `x₁ + x₂ > 0`。

```
          x₂
           │  ╱
           │ ╱   → 全放行
  ─────────┼╱──────── x₁
          ╱│
         ╱ │   → 全拦下
```

拿 `(2,2)` 检验：`2 + 2 = 4 ≤ 5`，**应该拦下**；但 `w·x = 4 > 0`，**放行了 → 判错**。

> 根子上：**无 bias 的分界线一定过原点，而"x₁+x₂ = 5"一定不过原点。两条不重合的直线，必定有地方判得不一样。**

## 1.5 ★★ 更狠的结论：整个网络被限制成了"齐次函数"

前面都在讲"一层"。但就算堆很多层、中间加 ReLU，**只要整个网络一个 bias 都没有**，就会有一个致命性质：

```
ReLU 有个特点：ReLU(k·z) = k·ReLU(z)      （只要 k > 0）

所以：f(2x) = 2·f(x)      f(10x) = 10·f(x)
             ↑
      输入放大几倍，输出就放大几倍
```

这叫**一阶齐次**。实测（两层无 bias 的 ReLU 网络）：

| 输入 | 输出 |
|---|---|
| `(3, 4)` | −1.6504 |
| `2 × (3, 4)` | **−3.3009** ← 正好 2 倍 |
| `10 × (3, 4)` | **−16.5044** ← 正好 10 倍 |

### 这个性质的真正后果

**判断只看"方向"，不看"大小"。**

```
(3, 4)  和  2×(3,4) = (6,8)   →  网络给出完全一样的结论（只是数值差倍数）
```

于是"**总量超过 5 才算数**"这种带**绝对门槛**的规则，它**天生学不会**：

```
同一个方向 (3,4)，只把大小缩放一下：
   缩放 1.0  → x₁+x₂ = 7.0   → 放行 ✓
   缩放 0.5  → x₁+x₂ = 3.5   → 拦下 ✗   ← 结论可以翻转
   缩放 0.2  → x₁+x₂ = 1.4   → 拦下 ✗

但齐次函数规定：方向和结论必须绑定 → 上面这种情况不可能出现
```

> ★★★ **一句话：没有 bias 的网络无法表达"量要够大"这件事 —— 它只懂"比例"，不懂"绝对量级"。**

## 1.6 换个视角：bias 就是"一个永远等于 1 的输入"

这是理解 bias 最直白的方式：

```
把 b 看成 w₀·x₀，其中 x₀ 永远等于 1：

   y = w₁x₁ + w₂x₂ + b
     = w₁x₁ + w₂x₂ + w₀·1        ← w₀ 就是 b

输入本来是 (x₁, x₂)，现在变成 (x₁, x₂, 1)
```

**为什么这样就不受"过原点"限制了？**

```
二维时：原点 (0,0) 是一个特殊点，所有 w·x=0 的直线都被它拴住

加上"永远 =1"的第三个坐标后：
   原来的原点变成了 (0, 0, 1)  ← 不再是原点了！
   它可以被那个"过原点"的超平面正常地分到任意一侧
```

> **bias 的本质：把输入空间的维度 +1（加一个恒为 1 的维度），从而让分界线在原来的空间里不再受"必须穿过原点"的约束。**

# 欠账二：为什么是 `1/√in`

## 2.1 先问：为什么非得管权重的"大小"？

因为**不管的话，网络深了必然爆或者必然死**。这不是审美问题，是能不能训的问题。

```
放大 2 倍的一层，叠 10 层  →  放大 2¹⁰ = 1024 倍   → 💥 数值爆炸
缩小 0.5 倍的一层，叠 10 层 →  缩小 0.5¹⁰ ≈ 0.001  → 🪦 信号消失
```

**目标：让每一层的输入和输出"量级差不多"** —— 这样叠多少层都不会失衡。

## 2.2 核心事实：方差可以相加（不是标准差相加）

### 先说人话

两个独立随机的东西叠在一起，**"波动的平方"相加，不是"波动"相加**。

```
扔一次骰子：平均 3.5，波动（标准差）≈ 1.71
扔两次求和：平均 7.0，波动 ≈ 2.42  ← 不是 1.71×2 = 3.42，而是 1.71×√2

因为：√(1 + 1) = √2 ≈ 1.414，不是 1 + 1 = 2
```

**这就是勾股定理的形状：**

```
        ↗ 合起来的波动 = √(a² + b²)
       ╱
      ╱
  ───┴───
```

### 再说为什么

```
(a + b)² = a² + 2ab + b²
                ↑
        交叉项。当 a、b 独立（互不相关）时，
        有正有负，平均下来 = 0  →  消失

于是：(a+b)² 的平均 = a² 的平均 + b² 的平均
     即：  Var(a+b) = Var(a) + Var(b)      ← 方差可加！
```

> ★ **方差能加，标准差不能加** —— 因为方差是"平方"的世界，平方世界才有这个好性质。

### 所以 `in` 项相加时

```
y = w₁x₁ + w₂x₂ + ... + w_in·x_in

Var(y) = Var(w₁x₁) + Var(w₂x₂) + ... + Var(w_in·x_in)
       = in × Var(w·x)                   ← in 项，每项一样
```

## 2.3 反推 `1/√in`

**设定**：输入 x 已归一化（每个 x 的方差 ≈ 1），权重的方差是 `σ_w²`。

```
Var(y) = in × σ_w²

希望 Var(y) = 1（和输入一个量级）
    →  σ_w² = 1 / in
    →  σ_w  = 1 / √in     ★
```

> **口诀：输入越宽（`in` 越大），每个权重就压得越小；`in` 份小波动加起来，总量刚刚好。**

## 2.4 三种取法对比（这是"为什么不是别的"的关键）

输入宽度 `in = 1024`，输入 std = 1：

| 权重取法 | 单个权重 std | 输出 std | 后果 |
|---|---|---|---|
| `1`（不缩放）| 1.0 | **32.0** | 每层放大 32 倍 → **爆炸** |
| `1/in` | 0.000977 | **0.031** | 每层缩小 32 倍 → **信号消失** |
| **`1/√in`** | **0.03125** | **1.0** | ✅ **不变** |

```
为什么 "除以 in" 是错的？

   σ_w = 1/in   →   Var(y) = in × (1/in²) = 1/in
                 →   std(y) = 1/√in

   in 从 4 涨到 1024（256 倍），std 从 0.5 掉到 0.031（16 倍）
   → 每层都在衰减，深层网络还没学到东西，信号已经没了

为什么 "除以 √in" 是对的？

   Var(y) = in × (1/√in)² = in × (1/in) = 1
                 →   std(y) = 1   ← 与 in 无关，恒定
```

✅ **只有 `1/√in` 能让输出量级和 `in` 完全脱钩。** 这就是"尺度守恒"。

## 2.5 ★★ 意外收获：解开"0.58 之谜"

上次笔记里实测到"不管 in 是 4 还是 1024，输出 std 都稳定在 **0.58** 左右"，但没解释**为什么是 0.58 而不是 1**。现在能算了：

```
PyTorch 用的是【均匀分布】Uniform(-1/√in, +1/√in)，不是正态分布。

而：均匀分布 Uniform(-a, +a) 的标准差 = a / √3      ← 记住这个系数
    （正态分布 N(0,σ) 的标准差才 = σ）

代入 a = 1/√in：
    σ_w = 1 / (√3 · √in)

    Var(y) = in × σ_w²  =  in × 1/(3·in)  =  1/3

    std(y) = √(1/3) = 1/√3 ≈ 0.5774     ★★ 就是那个 0.58！
```

**实测验证**（`nn.Linear(in, 256)`，2000 个随机样本）：

| `in` | weight 边界 `1/√in` | 实测输出 std | 理论 `1/√3` |
|---|---|---|---|
| 4 | 0.500000 | 0.6513 | 0.577350 |
| 16 | 0.250000 | 0.5940 | 0.577350 |
| 64 | 0.125000 | 0.5850 | 0.577350 |
| 1024 | 0.031250 | **0.5776** | 0.577350 |
| 4096 | 0.015625 | **0.5774** | 0.577350 |

> ★ **`in` 越大越精确地收敛到 `1/√3`。**
> **所以那个"难看的 0.58"完全不是实验噪声 —— 它是均匀分布的 `1/√3` 系数造成的，精确可预测。**

## 2.6 顺带回答：为什么是 `in` 而不是 `out`？

因为**前向计算 y 时，是沿着 `in` 这一维做累加**（`Σᵢ wᵢxᵢ`）。方差是在这个累加过程中攒起来的。

- 关心"信号前向传播时不爆炸" → 看 `in`（fan_in）
- 关心"梯度反向传播时不爆炸" → 看 `out`（fan_out）

PyTorch 默认按 **fan_in** 定（配合前向稳定）。

# 欠账三：线性层梯度公式怎么来的

## 3.0 先说清楚"梯度"到底要算什么

```
优化器唯一会做的事：w ← w − lr × (∂L/∂w)

所以我们要的是：∂L/∂w  =  "把 w 调大一点点，loss 会怎么变"
```

**整个推导只有一个工具：链式法则。**

```
L 依赖 y，y 依赖 w     →     ∂L/∂w = (∂L/∂y) × (∂y/∂w)
                                        ↑         ↑
                                  "上游传来的"  "本层自己的"
```

**给它起个名字：`g = ∂L/∂y`，叫"上游梯度"。** 它的含义是：
> **"你这一层的输出偏了多少、往哪个方向偏，会让最终的 loss 变好。"**

## 3.1 第 1 步：最简单的情形 —— 一个输入、一个输出

```
y = w · x          （w、x、y 都是标量）

∂L/∂w = (∂L/∂y) · (∂y/∂w) = g · x
                          ↑
                    y = wx 对 w 求导 = x
```

> ★★ **结论：`∂L/∂w = 上游梯度 g × 输入 x`**

### 这个公式的直觉

**"谁参与得多，谁背的锅大。"**

```
x = 3 和 x = 4 两个输入，都要经过 w
w 对 y 的影响被 x 放大（x 越大，w 动一点点，y 变化越大）
反向也一样：x 越大，w 收到的梯度越大

          上游说："这次偏高了"       →  g = +1
             ↓
          x=3 的那个权重 → grad = 1 × 3 = 3
          x=4 的那个权重 → grad = 1 × 4 = 4   ← 责任更大，改得更多
```

## 3.2 第 2 步：加输入 —— 多输入、单输出

```
y = w₁x₁ + w₂x₂ + ... + w_in·x_in = Σᵢ wᵢxᵢ

∂L/∂wᵢ = g · xᵢ          ← 每个权重各管各的输入

向量写法：∂L/∂w = g · xᵀ      ★
```

**实测**：`w = [1, 1]`，`x = [3, 4]`，`y = 7`，`L = y`（所以 `g = 1`）：

```python
l = nn.Linear(2, 1)
l.weight = [[1., 1.]],  l.bias = 0
x = [[3., 4.]]

l(x).sum().backward()
l.weight.grad  →  [[3., 4.]]      ← 正好等于输入 x！
```

> ★ **`∂L/∂w = g · xᵀ` 的含义：梯度就是"上游梯度"乘以"输入"，逐元素相乘。**

## 3.3 第 3 步：加输出 —— 多输入、多输出 ★ 关键一步

```
y_j = Σᵢ W_ji · xᵢ            （W 的形状是 (out, in)）

∂L/∂W_ji = g_j · xᵢ           （第 j 个输出的上游梯度 × 第 i 个输入）

矩阵写法：∂L/∂W = g xᵀ        （g 是 (out,) 向量，x 是 (in,) 向量）
                ↑
           这是一个【外积】，结果形状 = (out, in)
```

### ★ 顺带解释了一个一直没说透的问题：`weight` 为什么是 `(out, in)` 形状？

**因为梯度必须和它同形，而外积 `g xᵀ` 天生就是 `(out, in)`。**

```
g 是 (out,)      →    ┌ g₁ ┐
                      │ g₂ │
                      └ g₃ ┘
x 是 (in,)       →    [ x₁  x₂  x₃  x₄ ]

外积 =           ┌ g₁x₁  g₁x₂  g₁x₃  g₁x₄ ┐   ← 第 1 个输出的"责任分配"
                 │ g₂x₁  g₂x₂  g₂x₃  g₂x₄ │   ← 第 2 个输出的
                 └ g₃x₁  g₃x₂  g₃x₃  g₃x₄ ┘   ← 第 3 个输出的
                    ↑
             每行都是"输入 x"乘上那一行自己的上游梯度
```

**实测**：`W` 为 `(2,3)`，`x = [1,1,1]`：

```python
y = [[6., 1.]]              # 上游梯度 g = [1, 1]（因为 L = y.sum()）
l2.weight.grad  →  [[1., 1., 1.],
                    [1., 1., 1.]]   ← 每行都是 [1,1,1] = g_j × x
```

## 3.4 第 4 步：加 batch —— 梯度**累加**

一批 3 个样本，loss 是它们加起来（或平均）：

```
∂L/∂W = ∂L/∂W|样本1 + ∂L/∂W|样本2 + ∂L/∂W|样本3
      = g₁x₁ᵀ + g₂x₂ᵀ + g₃x₃ᵀ
```

**实测**：`W = [1, 1]`，三个样本 `x = [1,0] / [0,1] / [2,2]`：

```python
y = [1., 1., 4.]
W.grad  →  [[3., 3.]]

验算：[1,0] + [0,1] + [2,2] = [3, 3]   ✅
```

> ★ **含义：batch 里每个样本都为同一个权重"投一票"，最后叠加。** 样本越多，梯度越稳（噪声互相抵消）。

## 3.5 ★★ 把两处"累加"统一起来

上次笔记里，Linear 和 Conv 的梯度看起来是两回事：

| | 上次的说法 |
|---|---|
| Linear | "每个权重只用一次 → 梯度 = 对应的输入" |
| Conv | "同一个核复用 N 次 → 梯度 = N 个位置的累加" |

**其实它们是同一条规则：**

```
★★ 同一个参数被用了几次，它的梯度就累加几份。★★

   Linear：沿【batch 维度】复用 → batch 有 3 个样本，就累加 3 份
   Conv  ：沿【空间维度】复用 → 核扫过 9 个位置，就累加 9 份
   Linear：其实在 in 维度上不复用（每个 wᵢ 只配一个 xᵢ）
```

**"参数共享"和"梯度累加"是同一枚硬币的两面：**
> **共享 = 一个参数被用在多处；累加 = 那些地方的"责任"合并到同一个人头上。**

**好处**：规律能用在全图所有位置（这是卷积的威力来源）。
**代价**：梯度必须合并，所以同一个核的梯度是"很多份意见的总和"。

## 3.6 第 5 步：bias 的梯度 —— 为什么它"永远有人推"

```
y_j = Σᵢ W_ji xᵢ + b_j

∂y_j/∂b_j = 1          ← 链式法则的前半段，恒等于 1
                        （b_j 加多少，y_j 就加多少，一阶导就是常数 1）

∂L/∂b_j = g_j × 1 = g_j
```

> ⚠️ **修正一下上次笔记的措辞**：
> 上次写的是"bias 的梯度恒为 1"。**准确说是 `∂y/∂b = 1`**（本层对 bias 的导数恒为 1）；
> 而**真正拿去更新的是 `∂L/∂b = g`** —— 它等于上游梯度本身，`g` 变了它也跟着变。
>
> **不变的是"不乘输入"这件事**：bias 的梯度里**没有 `x` 这一项**。

**为什么说它"永远有人推"？**

```
∂L/∂wᵢ = g · xᵢ      ← 如果 xᵢ 恰好是 0，这个权重这次就不动了
∂L/∂b  = g           ← 只要 g ≠ 0，bias 就一定会动
```

**实测**：`w = [1,1]`，`x = [3,4]`，`L = y`：

```python
W.grad  →  [[3., 4.]]    ← 被输入 x 缩放
b.grad  →  [1.]          ← 就是 g 本身，没有 x
```

## 3.7 第 6 步（补全）：梯度怎么继续往上传

前面算的都是"本层的参数"。但前一层还等着梯度呢：

```
∂L/∂xᵢ = Σⱼ g_j · W_ji

矩阵写法：∂L/∂x = Wᵀ g        ★
```

**实测验证**（`W = [[1,2,3],[0,1,0]]`，`x = [1,1,1]`）：
```
Wᵀ g 的第 i 个分量 = g₁W₁ᵢ + g₂W₂ᵢ
```

> ★ **`∂L/∂x = Wᵀ g` 就是"反向传播"这个名字的由来：**
> 前向是 `y = Wx`，反向是 `∂L/∂x = Wᵀg` —— **同一个矩阵，转置一下，就往回传了。**
>
> **没有这一步，反向传播链条就断了，深层网络根本无法训练。**

## 3.8 全部公式汇总（一页纸）

| 量 | 公式 | 记忆点 |
|---|---|---|
| 上游梯度 | `g = ∂L/∂y` | 从后面传进来的"抱怨" |
| 对权重 | `∂L/∂W = g xᵀ` | **外积**，形状 `(out, in)`，正好和 W 同形 |
| 对 bias | `∂L/∂b = g` | **不乘输入** |
| 传给前一层 | `∂L/∂x = Wᵀ g` | **转置一下就往回传** |
| batch | 上述各项**逐样本累加** | 同一参数用几次就加几份 |

> **一句话总结全部：**
> **"梯度 = 上游传来的抱怨 × 自己参与的程度。"**
> - 权重的"参与程度" = 输入 `x`（还带 batch 累加）
> - bias 的"参与程度" = 1（恒定，所以永远在动）
> - 往上传的"参与程度" = `Wᵀ`
